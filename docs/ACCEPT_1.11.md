# 推车 1.11 验收单（人工）

给明天在推车前的人用。**先跑脚本，脚本能看出来的都交给它；人只做非动手不可的。**
步骤按人在车前的动作顺序排：看主屏 → 看副屏 → 插网线 → 接键鼠和 HDMI → 接串口 → 打标签 → 最后拔市电（会关机，放最后）。

每步写了：做什么、应该看到什么、对应哪个 issue、过了能关哪个。看不懂 issue 号没关系，每步开头一句话说清楚这功能是干什么的。
带 **【要外部条件】** 的步骤，条件不够就跳过，在表里写"没测"，**不要关**对应的 issue。

`<推车>` = 推车 ssh 地址；`<MAC>` = 待装机的网卡 MAC；`<by-id>` = CH9329 键鼠线在 `/dev/serial/by-id/` 下的名字（`ls /dev/serial/by-id/ | grep 1a86`）。

## 1. 先确认版本，跑脚本（5 分钟）

**做什么**

```bash
ssh <推车>
cat /opt/pxe/VERSION /opt/pxe/BUILD
```

- 不是 `1.11.00`：先照 [`DEPLOY_1.11.00.md`](DEPLOY_1.11.00.md) 部署，再回来。
- 是 `1.11.00`：把验收脚本拷上去跑（脚本**只读**，不改任何东西，可以随便跑几遍）：

```bash
# 开发机上
scp scripts/cart_accept.py scripts/accept_core.py <推车>:/tmp/accept/
# (有 scripts/accept-manifest.json 也一起拷, 能逐个比对文件内容; 没有就少一项, 不影响别的)

# 推车上
sudo python3 /tmp/accept/cart_accept.py | tee ~/accept-1.11-run1.txt
```

**应该看到**：每行一个 `[PASS] / [FAIL] / [SKIP] / [人工]`，后面是 issue 号和一句原因；最后有汇总，FAIL 和"人工"再列一遍。

- 这时候还没接线，下面这些出 SKIP / 人工 / FAIL 都是正常的，**先别管**：LLDP 对端（#14）、CH9329 键鼠线（#9）、标签机（#20）、串口操作头（#15）、Clonezilla 文件（#18）、自己发地址限时（#11）。
- 其余的 **FAIL 要先处理**（原因那句话一般就说了怎么修），修不了的记下来，问 维护者。
- 只想重跑某一项：`sudo python3 /tmp/accept/cart_accept.py --only '#14'`（按 issue 号或名字里的字过滤）。

## 2. 看主屏（车机）—— 不用接任何线

### 2.1 开机自检和字体（#28、#27）

> 这一版把车机换成了 CDE 风格（老式 Unix 工作站那种：深色、按钮凸起、输入框凹进去），字换成了 Unifont 点阵字。

**做什么**：`sudo systemctl restart kiosk`，看主屏从开机自检开始走一遍。

**应该看到**

- 开机自检里有一行 `UI FONT ... OK UNIFONT 16PX`。如果是 `WARN FALLBACK NOTO`，说明字体没装上（回 DEPLOY 第 4 步）。
- 字是点阵的、清楚、不糊；中文英文都不缺字（没有方框 / 问号）。

### 2.2 每个界面过一遍（#27、#28）

**做什么**：解锁后依次打开：主界面 → 锁屏 → 装机解锁对话框（打开就行，点取消）→ 网络（网口模式、无线）→ 串口面板 → 网络唤醒 → Kickstart 编辑 → 随便一个确认框。每个**用手机拍一张**。

**应该看到**

- 按钮是凸的，面板 / 输入框是凹的，对话框有标题条。
- 原来顶上那排小指示灯（执行器条）挪到了**屏幕底下**，像一排前面板按钮；串口操作头（con-1~4）比原来大。
- **没有看不清的字**：灰底上的灰字、确认框里的小字都能读。看不清的拍下来，记哪个界面哪行。
- 按钮文字没被截断、没有挤出框。

**过了**：#28 可以关；#27（主题规范化）的验收就是"实机每个界面过一遍"，一起关。照片发给 维护者 留底。

### 2.3 深 / 浅（#31）——**只看脚本，不看界面**

> #31 只做了"按日出日落算现在该深色还是浅色"，算出来写进状态快照；**界面跟着切换是 #32，还没做**。所以屏幕一直是深色是对的。

**做什么**：看第 1 步脚本里这两行：`theme.json (日出日落)`、`深浅模式进快照`。

**应该看到**

- `theme.json` 那行 PASS，经纬度是推车所在城市（不是样例里的格林尼治 51.4779,-0.0015）。是"人工 / 没有 theme.json"：照 DEPLOY 第 6 步配上再跑。
- `深浅模式进快照`：白天显示 `现在 light`、晚上 `现在 dark`；"下次切换"的时间 ≈ 今天当地日落（或明天日出）**加 20 分钟**缓冲。拿手机天气 App 的日出日落时间对一下，差 2 分钟以内就对。

**过了**：#31 可以关（在 issue 里贴一下脚本这两行和手机上的日落时间）。

## 4. 插网线

### 4.1 LLDP：插上网线就知道对面是哪台交换机哪个口（#14）**【要外部条件：开了 LLDP 的交换机】**

**做什么**：拿网线把推车 **LAN2（管理口）** 插到交换机上随便一个口（LAN1 是装机口，**别插有人用的交换机**，见 4.3）。等 30 秒。

**应该看到**

- 副屏 / 车机状态板的 LAN2 那行后面出现"对端 <交换机名> <口名>"，比如 `对端 SW-1 GE0/0/12`，有 VLAN 的还带 VLAN。
- 跑 `sudo python3 /tmp/accept/cart_accept.py --only '#14'` → `LLDP 对端` PASS，原因里就是那个交换机和口。
- 拔掉网线：过一会儿（交换机发的有效期，一般 2 分钟）那行**变灰**并写"x 分钟前"；再过 10 分钟消失。换插另一个口，显示跟着变。

**过了**：#14 可以关。

### 4.2 网口静态地址全手动（#13，顺带 #12 / #25）

> 以前填静态地址时推车会"猜"子网是 /24，对面不是 /24 就配错了。现在必须人自己写 `地址/前缀`。

**做什么**（在**车机屏幕上**做，别在 ssh 里——改 LAN2 会断经它的远程连接；无线和 tailscale 还在）：网络 → 网口模式 → 选 LAN2 → 静态。

1. 地址只写 `192.0.2.50`（**不写 /前缀**）→ 点确定。
2. 改成 `192.0.2.50/23`，对端地址留空，网关、DNS 留空 → 确定。
3. 确认框弹出来后看一眼，点"是"。
4. 最后把 LAN2 切回 DHCP。

**应该看到**

1. 第 1 下**报错**，提示要补前缀；**不会**默默按 /24 配上。
2. 对端留空也能建。
3. 确认框列出要执行的命令和撤销（undo）命令，写清"原来 / 改为"。
4. `ip -4 addr show enp3s0` 里是 `/23`（按人填的来）。切回 DHCP 后地址恢复正常、远程又能连上。

**过了**：#13 可以关。#12、#25（网口模式重构、静态加网关 DNS）也是这个面板，顺手试了网关 / DNS 没问题可以在 issue 里留言，关不关问 维护者。

### 4.3 装机口自己发地址限时 30 分钟（#11 的一部分）**【要外部条件：待装机】**

> 装机口（LAN1）所在网络里没有别的 DHCP 时，推车自己给整个网段发地址。这很危险，所以限时：默认 30 分钟到点自动停发。

**做什么**：网线直连 **推车 LAN1 ↔ 待装机**（中间不要交换机）。确认 PXE 服务在跑：`systemctl is-active pxe-server`，不是 active 就 `sudo systemctl start pxe-server`。

**应该看到**

- 车机顶栏下面一整条**红色横条**："正在给整个网段发地址 剩 mm:ss"，锁屏右上角和副屏头部也有。
- 跑 `--only '#11'` → `自己发地址限时` PASS，"限时 30 分钟，剩 xx 分钟"。
- 点那条红条 → 确认 → 续期，剩余时间重新从 30:00 开始。
- （可选，要等）到点后红条变成"已到时、已停发"，events.log 有一行 `[pxe]`，配了推送的话手机收到。想快点验：临时在 `/etc/ops-cart/pxe.env` 加 `PXE_SERVE_MINUTES=2`，`sudo systemctl restart pxe-server`，验完删掉这行再重启。

**过了**：在 #11 里留言"限时验过"。#11 本身还包括数据盘、WinPE、Samba 等，**不关**，等 维护者 看。

## 5. 接 HDMI 和键鼠线，让屏幕配方自动进网络启动（#17）**【要外部条件：待装机】**

> 推车看着待装机的屏幕（HDMI 采集）、自己按键（CH9329），开机时自动按启动菜单键、选网络启动。

**做什么**：HDMI 线、CH9329 键鼠线接到待装机；LAN1 网线接着待装机（第 4.3 步那根）。待装机先关机。

1. 先只看不按：`sudo python3 /opt/pxe/recipe.py boot-pxe --dry-run`，跑起来后给待装机上电。
2. 真跑：待装机关机，`sudo python3 /opt/pxe/recipe.py boot-pxe --timeout 120`，跑起来后上电。不认启动提示的机器加 `--key f12`（按机器厂商换键）。

**应该看到**

1. dry-run：终端打印认到的字（比如 "F12 Boot Menu"），**一个键都不发**；`/run/ops-cart/recipe-*` 下留了截图和 `log.jsonl`。
2. 真跑：屏幕上出现启动菜单、自动选中网络启动（PXE / Network / IPv4）、回车，待装机开始 PXE，出现推车的救援菜单。退出码 0。
3. 配方里没有进 BIOS 设置、没有"保存"类按键。

**过了**：#17 可以关。不过的话把 `/run/ops-cart/recipe-*` 整个目录拷回来给 维护者（重启推车会清掉）。

## 6. 键鼠：人在看预览时 Agent 也能打字，人永远优先（#9）**【要外部条件：待装机】**

> 以前车机开着预览，Agent 一个键也发不出去。现在键鼠由一个常驻代理统一管：人优先，Agent 排队，能急停。

**做什么**：待装机开到一个能打字的地方（登录界面、救援 shell、或 GRUB 按 `e` 的编辑界面都行）。**车机上开着预览**。

1. 笔记本上：`ssh <推车> python3 /opt/pxe/ch9329.py --port /dev/serial/by-id/<by-id> type "hello from agent"`
2. 再发一长串：`... type "aaaaaaaa...（200 个字母）"`，发的同时人在**推车键盘**上连按几下键。
3. 急停：`ssh <推车> python3 /opt/pxe/ch9329.py estop --all`，然后再发一次 type。
4. 解除：`ssh <推车> python3 /opt/pxe/ch9329.py --src human resume --all`，再发一次 type。

**应该看到**

1. 预览里出现 `hello from agent`（**开着预览也能打**，这是这次修的）。
2. 人一按键，Agent 的字**停下**；人停手 3 秒后接着打完，不丢不乱序。
3. 急停后 Agent 剩下没发的字丢掉；再发被拒（"急停中"之类），**不会**往待装机插任何键。
4. 解除后又能发。
5. `sudo tail /var/log/ops-cart/kvm.log`：每次都有一行，写着来源 agent / human。

**过了**：#9 可以关。

## 7. Agent 申请 PXE 解锁，人照抄确认码才生效（#24）**【要外部条件：待装机 + Agent】**

> Agent 不能自己让一台机器进装机菜单（装机会清盘），只能"申请"；车机弹框，人照抄屏幕上的确认码才解锁。

**做什么**

在装了 Claude Code 的电脑上接推车的 MCP（stdio 走 ssh，ssh 本身就是认证）：

```bash
claude mcp add cart -- ssh <推车> sudo python3 /opt/pxe/cart_mcp.py stdio
```

（待核对：`sudo` 要免密，不然 stdio 会卡在输密码。没有 Claude Code 的话，在推车上手敲：
`printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"pxe_request","arguments":{"purpose":"winpe","mac":"<MAC>"}}}' | sudo python3 /opt/pxe/cart_mcp.py stdio`）

1. 让 Agent 调 `pxe_request`，用途 `winpe`（进 PE，不动硬盘；要推车上 `win/` 文件齐全，不齐会被拒）或 `rocky`（**会清空待装机硬盘**，只在能清的机器上用），给 `<MAC>`。
2. 看 Agent 拿到的回复。
3. 车机上弹出"Agent PXE 解锁申请"框：先**故意抄错**确认码 → 确认。
4. 再照抄正确的确认码 → 确认。
5. 让 Agent 调 `pxe_requests` 看结果，再调 `pxe_retire` 提前上锁。
6. 再申请一次，这次点车机底下的"Agent 全部急停"，然后看那条申请。
7. 浏览器打开网页口 →「PXE 日志」页。

**应该看到**

1. 车机（不在锁屏 / 自检页时）自动弹出申请框：谁申请的、用途、清单（哪台 MAC、什么菜单）、一个大号确认码。
2. **Agent 的回复里没有确认码**，也没有清单摘要。
3. 抄错：被拒，确认码原地换一个（输错不限次数）。
4. 抄对：解锁，待装机重启 PXE 能看到对应菜单。
5. `pxe_requests` 显示 armed；`pxe_retire` 后菜单清掉，待装机再 PXE 只有救援菜单。
6. 全部急停后，在等的申请作废（dropped）。之后到车机上解除急停。
7. 网页「PXE 日志」按 MAC 分组列出刚才这些事；**网页上没有确认 / 拒绝按钮，也看不到确认码**。

**过了**：#24 可以关。

## 8. 接串口（交换机 console）

把 console 线从推车串口操作头（con-1~4 里任意一个，记住是几号，下面叫"槽位 N"）接到交换机 console 口。先跑一遍 `--only '#15'`，`串口操作头 /dev/con-*` 和 `conbroker` 两行要 PASS。

### 8.1 一键只读巡检（#15）**【要外部条件：交换机 console】**

> 一键把交换机的配置、状态用只读命令（`display` / `show`）读一遍存档，跟上次比有没有变。

**做什么**：车机 → 串口面板 → 选槽位 N（能看到交换机提示符，比如 `<SW-1>`）→ 点「巡检」。等它跑完，再点一次。

**应该看到**

- 控制台里一段摘要和存档路径（在 `/var/log/ops-cart/survey/` 下）。
- 第二次跑写"和上一份比：没有变化"（时钟、uptime 这类每次都变的行不算）。
- 交换机上没有任何配置被改（巡检只发 display / show）。

**过了**：#15 可以关。

### 8.2 Agent 只读看串口、截屏、看推车状态（#19）**【要外部条件：Agent】**

**做什么**：在 Claude Code 里（接法见第 7 步）让它：列执行绪、读槽位 N 最近 50 行、截一张待装机屏幕、看推车状态。

**应该看到**

- 列执行绪：槽位 N 有线、有服务，名字是交换机提示符里的名字（比如 `SW-1`），**永远带槽位号**。
- 读输出就是串口面板里那些行；截图是待装机当前画面（推车锁着屏也能截）；推车状态里有 UPS、LAN1/LAN2 的 LLDP 对端。
- `sudo tail /var/log/ops-cart/mcp-audit.log`：每次调用一行（谁、哪个工具、参数）。
- （可选）HTTP 方式默认不开；要验的话照 README 配 `/etc/ops-cart/mcp.json` 令牌、`enable --now cart-mcp`，不带令牌访问应被拒（401）。

**过了**：#19 可以关。

### 8.3 Agent 写串口：租约、闸门、人确认、急停（#21，顺带 #23）**【要外部条件：交换机 console + Agent】**

> Agent 可以往交换机敲命令，但：要先拿"写租约"（有期限、要续）；只读命令直接发；别的命令挂起等人在推车上确认；带 save / reboot 这类高危词的永远要人确认；任何人一键急停。

**做什么**（让 Agent 依次做，人看车机）：

1. `lease_acquire` 槽位 N；`send_command` 发 `display version`。
2. `send_command` 发 `screen-length 0 temporary`（华为，只影响这次登录的分屏，无害）。
3. 车机上点槽位 N 那个**黄色闪烁**的方块 → 确认框里先点"拒绝"；让 Agent 再发一次 → 这次点"确认"。
4. `send_command` 发 `save`。车机确认框里**点拒绝**（千万别确认）。
5. 车机上点"Agent 全部急停"；让 Agent 再发 `display clock`。
6. ssh 上推车跑 `sudo python3 /opt/pxe/cart_mcp.py resume all`；再到车机上点方块 → 解除。
7. 让 Agent 拿到租约后**不续**，等 70 秒再发命令。
8. （有网页口的话）浏览器 →「Agent」页看挂起的命令。

**应该看到**

1. `display version` 直接发出，Agent 拿到输出；操作头方块 Agent 输入时紫色闪。
2. 第二条挂起（`status=pending`），车机方块变**黄色闪**，副屏同一个方块也黄，并写挂起数。
3. 拒绝 → 没发到交换机；确认 → 发出，交换机上能看到。
4. `save` 的确认框会**再问一次**（高危词）；拒绝后交换机上没有保存。
5. 急停：方块变红；Agent 的命令被拒；**没有任何字节发到交换机**。
6. 经 ssh 的 `resume` 被拒（解除只认推车本机）；车机上点解除才恢复。
7. 租约过期，命令被拒，要重新 `lease_acquire`。
8. 网页上只有"急停"和"拒绝"，没有"确认"和"解除"。
9. `/var/log/ops-cart/serial-slot<N>.log` 每条都有：时间、谁、命令、闸门结果、确认 / 急停事件。

**过了**：#21 可以关；#23（确认 UI）一起关。第 2 层决策模型（#22）默认关着，这次不验。

## 9. 打标签（#20）**【要外部条件：TSC 标签机 + 纸 + 碳带 + Agent】**

> Agent 能出线缆标签：先预览、检查（只许 ASCII、不超长、不出界），打一张样，人看过才许批量。

**做什么**：标签机接推车 USB、开机、装好纸。跑 `--only '#20'`，`标签机 /dev/usb/lp0` 要 PASS。然后让 Agent：

1. `label_printer_status`。
2. 用第 4.1 步 LLDP 看到的对端（比如 `SW-1 GE0/0/12`）做一张线缆标签 `label_preview`，再 `label_print` 一张。
3. 不带 `proof` 直接要打 3 张。
4. 带上第 2 步回的 `proof` 和一句人说的确认话，再打 3 张。
5. 打开标签机盖子，再让它打一张。
6. 让它预览一张带中文或超长的标签。

**应该看到**

1. 状态 ok。
2. 预览回检查结果和 SVG；打出来**一张**：上下对折后字是正的、没有被切、两半对得上。
3. 被拒（批量要先打样）。
4. 打出 3 张。
5. 被拒，说开盖。
6. 被拒，说明哪里不合规（非 ASCII / 超长）。

**过了**：#20 可以关。

## 10. 最后：拔市电，UPS 两段式关机（#4）**【要外部条件：半小时电池时间；会把推车关掉，放最后】**

> 停电后推车靠 UPS 撑着。电量 ≤40%（或 UPS 估计剩不到 15 分钟）先琥珀色**预告**；到 15% 开始 **30 秒倒计时**，倒计时期间插回市电就取消；走完才正常关机。

**做什么**：先确认手头没有正在装的机器、串口没人在用。拔掉推车的市电（UPS 输入），推车照常开着等，每隔几分钟看一眼。

1. 等到预告出来 → **插回市电**。
2. 再拔。等到倒计时出来 → 倒计时中**插回市电**。
3. （想验关机就做）再拔，让倒计时走完。
4. 推车关机后插回市电，开机后看日志。

**应该看到**

- 拔掉后几秒内（有 hidraw 的话；只有 upower 要 1–2 分钟）副屏 UPS 行变"市电断开 · 电池 xx%"。按约 3.7%/分钟掉电，从满电到预告大约 20 分钟。
1. 预告：车机顶栏、副屏横条一条**琥珀色**"电池约剩 x 分钟，到 15% 自动关机，请插回市电"，锁屏右上角也有；配了推送的话手机收到一条。插回市电后横条消失。
2. 倒计时：变**红色**"电量 15%，xx 秒后自动关机 · 插回市电可取消"；插回后取消，不关机。
3. 30 秒走完：推车正常关机（不是断电）。
4. `sudo cat /var/log/ops-cart/ups.log`：有"低电量预告""电量 15% 到阈值""市电恢复, 取消关机倒计时""倒计时结束, 正常关机"这几种行；`journalctl -b -1 | tail` 是正常关机的样子。
- 开机后再跑一遍脚本，`ups.log (断电才写)` 变 PASS。

**过了**：#4 可以关。
